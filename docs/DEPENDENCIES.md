M03 uses the verified Flutter 3.47.5 stable / Dart 3.13.4 SDK and committed package locks. This is an engineering inventory, not legal approval or a complete vulnerability audit. Re-run review after any dependency change and at M13/M14. [The generated resolved inventory](verification/evidence/M03/dependencies.json) records versions, dependency edges, license-source hashes and runtime/build versus development closure without machine paths.

Version selection used primary package metadata and actual cached source/lockfiles, rather than remembered versions. go_router 18 requires the SDK's newer Material/Cupertino UI packages; installed Flutter/Dart meet its constraints. path_provider's current Android/Foundation implementations use JNI/Objective-C FFI and native-asset hooks. They obtain local OS directories; no OAuth, service account, cloud database, login, analytics, crash service or media permission is added. Build hooks are code execution during dependency builds and are included in the resolved inventory; lockfile hashes and official maintainer review matter.

`flutter pub outdated --json` initially identified two compatible transitive updates (`vector_math` 2.4.4 and `vm_service` 15.4.0); both were resolved before final tests in root and preview locks. `material_color_utilities` 0.13.0 and `test_api` 0.7.12 are constrained by the pinned SDK, despite newer upstream versions. Do not override SDK constraints merely to remove an outdated warning. Pub's discontinued/retracted/advisory signals are limited metadata, not proof that every dependency/native binary is vulnerability-free.

The resolved graph contains 67 non-root packages: 59 in the normal dependency/build closure and eight development-only. This closure includes `flutter_test` because upstream `flutter_riverpod` 3.4.3 declares it as a normal dependency; it is not evidence that all test code is shipped after tree shaking. The inventory records 57 BSD-3-Clause, five MIT, four Apache-2.0 package license sources, plus the engine's **multi-license** third-party notices. Do not label the engine solely MIT/BSD. SDK packages without an individual LICENSE inherit the actual SDK LICENSE; each record says so. Automatic classification must fail for an unreviewed license rather than silently accepting it.

Flutter generates compiled license notices and the app exposes the native acknowledgments page in Settings. Keep upstream copyright/license notices when redistributing; review full engine/native/font notices in the final release artifact. MaterialIcons is CC BY 4.0, Roboto Apache-2.0; M02 review fonts were not copied into this repository. [Asset attribution](ASSET_ATTRIBUTION.md) and [original native asset hashes](../assets/branding/NATIVE_ASSETS.json) distinguish project artwork from SDK fonts.

The actual debug APK notice audit found Riverpod/go_router/path_provider and engine notices but omitted Material Icons' CC BY 4.0 text despite packaging the font. M03 explicitly bundles the unchanged SDK license and registers an attributed acknowledgments entry; an executable test checks the loaded entry. Preserve this supplement in future artifacts. This finding was fixed, rather than assuming automatic notices were complete.

The Gradle distribution SHA-256 was read from the [official distribution checksum](https://services.gradle.org/distributions/gradle-9.3.1-all.zip.sha256) and pinned. The actual local build selects Android Studio JDK 25.0.3. No global Java configuration was changed.
