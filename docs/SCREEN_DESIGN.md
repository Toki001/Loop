# Native screen and state contract — M02

This is the detailed design handoff for PRODUCT's 23 screens, supported by the native [preview harness](../design_preview/README.md). It is a design contract, not proof of stored data, media capture, native integration or user research. Use [WORKFLOWS.md](WORKFLOWS.md), [DESIGN.md](DESIGN.md) and [DATA_AND_METRICS.md](DATA_AND_METRICS.md) for behavior, tokens and formulas.

## Shared layout and state rules

Use one safe-area scaffold and primary vertical scroll, 16pt compact/20pt common horizontal margins and 720pt maximum content width. A 4pt base/8pt rhythm supplies 4/8/12/16/20/24/32/40 gaps; 16pt cards, 12pt controls, no arbitrary page-specific radii. A tablet grows gutters before text measure; related evidence can use two columns, forms stay comfortably readable. Respect keyboard insets; do not hide Save/Stop behind the keyboard. Portrait and landscape keep actions reachable; no orientation lock is assumed.

Normal text uses the platform system sans, 15–16pt body, 13pt supporting, 20pt section, 28pt heading, 34pt hero, size-specific leading/tracking. Do not clamp OS text scale. At 200%, ordinary text wraps, evidence stacks and content scrolls. Default five labeled bottom destinations become a labeled Navigate sheet plus direct Practice action above 125% text, keeping every destination reachable without clipped labels. Current screen remains in the header. Active practice has pinned Pause/Resume and Finish controls independently of scrollable exercise text; large type stacks them vertically. Reflection Save has a keyboard-aware pinned action bar, verified with a compact 200% keyboard case.

Every control has 48×48 logical minimum hit bounds, accessible purpose/state, focus, native pressed/keyboard activation, disabled explanation where relevant and no color-only meaning. Inputs keep visible labels, helper/error text and meaningful keyboard type. Timer has a verbal duration, not a screen-reader announcement every second. Charts have equivalent values/dates/units; photo sliders have buttons/two-up fallback; audio never needs a gesture to operate. System dark/light, large/bold type, contrast/reduced motion and keyboard/switch navigation are design requirements; physical VoiceOver/TalkBack evidence remains M13/M14.

State vocabulary used below:

- **Loading:** truthful local work status; no arbitrary wait. Long media work has cancel/retry if safe; no fabricated percent. Optional static skeleton/notice instead of oscillation for reduced motion.
- **Empty:** explain why and provide the one real next action; no seeded retail statistics, stock evidence or fake comparison.
- **Validation:** inline specific error and retained input; choose sensible numeric keyboard but validate in domain code too. Reflection/media remain optional.
- **Saving/success:** serial/idempotent action, visible busy state and actual repository completion before confirmation; retry preserves the draft. No success on a timer or mock response.
- **Error:** persistent recovery guidance where data is at risk, never stack trace, personal path or silent reset. Distinguish unavailable storage, missing evidence, malformed import and permission denial.
- **Permission:** optional contextual request, denial alternative and appropriate retry/settings; no prompt on launch and no permission loop.
- **Disabled:** retain comprehensible label and reason; hide incomplete features in retail rather than exposing dead controls. Destructive confirmations name scope/count and irrevocability; normal navigation does not require confirmation.

## Motion, feedback and sign-off

Native press feedback begins immediately; commit occurs on activation/release. Custom feedback duration is 120ms, navigation 200ms, sheet 240ms; do not delay inputs. No looping scenery, timer pulses, compulsory celebration, scale-from-zero, or decorative charts. Gesture comparison tracks the finger and has a non-drag equivalent; native media interruptions must stop resources. Reduced movement is checked through Android disableAnimations and iOS reduceMotion (separate installed-SDK signals), yielding static/gentle feedback. Actual haptics are optional at meaningful committed events only.

M02 engineering review uses the existing Calm Momentum identity and Apple Design principles; unavailable UI/UX Pro Max, Hallmark and Emil tools are not fabricated. The review rejects gradients/vanity gauges/emoji navigation/card nesting/hidden focus and false measurements. Engineering sign-off follows actual contrast/layout/golden checks and sampled image review recorded in M02; it is not participant approval, legal clearance or physical-device accessibility certification. Those later gates remain visible.
